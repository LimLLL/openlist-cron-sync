# 剩余工作

## MVP待完成用户指南

以下必须在对应功能实现后、M8发布前完成，不是post-MVP：

| 指南                    | 内容                                                                                                                                                                              | 依赖      |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| 首次部署与管理员初始化  | Node/Docker、卷权限、密钥、改密、代理；初始随机密码写入stderr，会留在容器日志中；离线重置管理员密码的步骤；API文档公开开关                                                        | M0/M8     |
| OpenList账号与挂载配置  | 权限、base_path、静态token、refresh、非管理员前提                                                                                                                                 | M1        |
| 建立任务与dry-run解读   | 每目标模式、过滤、syncEmptyDirs、冲突、共同删除阈值                                                                                                                               | M2/M3b    |
| 取消、重启和unknown处理 | TTL风险、提前release与abandon的区别、计划内重启不取消远程task                                                                                                                     | M3a/M6    |
| 驱动兼容与云盘人工验证  | 矩阵各列含义及证据等级（源码推断/集成测试/人工验证）、异步受理驱动按成功计的后果（后台失败不可见、extras可能先删除、通知不追溯）、Temp幽灵与refresh、用户人工验证云盘并记录的步骤 | M3a/M6/M8 |
| relay排障               | 302、sign、长度、Range续传、spool磁盘与保留空间、低带宽、反代chunk大小与超时限制                                                                                                  | M3a       |
| Webhook与配置迁移       | 原始bytes验签、重复投递、secret补录、导入后Webhook URL复核                                                                                                                        | M7        |
| 备份、恢复和升级        | 备份前禁用Job、DB+key一致备份、旧备份远端不回退                                                                                                                                   | M8        |

指南用户步骤以真实CLI/API为准，不把尚未实现操作宣传为可用。当前[部署](design/deployment.md)、[安全](design/security.md)、[Relay](design/relay.md)提供实施所需的行为规范，驱动语义见[驱动矩阵](reference/driver-matrix.md)。

## Post-MVP

| 项目                         | 推迟原因及重启讨论条件                                                                                                                                                     |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Web 前端                     | backend-first；后端 MVP 发布后启动，基于已发布的 OpenAPI 契约                                                                                                              |
| 源端move                     | 必须先定义所有目标交付确认、后台copy完成、源运行中变化和失联恢复；同大小不证明内容相同，task_group.verifyAndRemove依赖存在性且清理失败可能只日志；不能最后目标move提前删源 |
| 常规复制后校验               | MVP明确不做；未来区分名称大小、hash与读取验证，需讨论权限、缓存和云API成本                                                                                                 |
| 版本管理                     | 当前不保存被删除的旧文件；版本目录、版本查询/恢复及原子切换需新需求                                                                                                        |
| 跨重启续传与共享下载         | 当前本服务重启后不续传旧multipart session，多目标时各自下载；跨重启续传需持久化块索引与session，共享下载需分组准入与引用计数                                               |
| SSE进度                      | 当前轮询够用；未来考虑连接生命周期、断线重放及鉴权                                                                                                                         |
| per-target filters           | 当前Job统一规则，避免各目标管理范围含义分裂                                                                                                                                |
| 通知适配器                   | Telegram/Bark/ServerChan等在Webhook稳定后按需求加入                                                                                                                        |
| 更强通知可靠性               | 当前best-effort；持久outbox/跨重启补投仅在明确要求后设计                                                                                                                   |
| 非空目录整批删除优化         | 当前逐文件和确认空目录，避免过滤绕过和目录任务子树句柄缺失                                                                                                                 |
| 完整Unicode/文件系统命名适配 | 简单fold只发现已知冲突，不能保证所有目标等价关系                                                                                                                           |
| 在线主密钥轮换工具           | 当前只定义维护前提，未提供在线轮换API或迁移工具                                                                                                                            |

双向同步和多副本部署明确非当前目标，不默认承诺某个未来版本实现。
