用途：说明如何阅读驱动矩阵、理解各类证据的可信程度，以及如何在自己的云盘上做人工验证并记录结果。

范围：面向使用 Local 以外存储的用户；矩阵本身见[驱动矩阵](../reference/driver-matrix.md)，产品政策见[驱动兼容性](../reference/driver-compatibility.md)。本文不扩大任何驱动的兼容承诺。

# 驱动兼容与云盘人工验证

本服务只通过 OpenList 的公开 API 读写文件，实际效果取决于目标存储使用的 OpenList 驱动。OpenList 上游有 86 个驱动，本项目无法逐一实测；使用前应先查矩阵，再在自己的环境里验证。

## 读懂驱动矩阵

| 列                                | 含义                                                                                                                                                            |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Copy（server_copy 同存储）        | 驱动的服务端复制行为。只影响创建方式选“服务端复制”的 Target；“后台受理，不等待完成”“空实现”“完成时机未知”都意味着 OpenList 返回成功不代表数据已落地             |
| Put（relay 写入；目标已有同名时） | 目标已有同名对象时驱动的底层行为。本服务总是先删除旧文件、确认原名消失后再上传，正常不会走到这条路径，只在缓存失真或竞态时有意义。“不可写”的驱动不能作为 Target |
| Remove（删除）                    | 是否实现删除。“不支持”时删除请求失败；“空实现”时请求成功但原名仍在，删除确认期限后记 failed DELETE_NOT_EFFECTIVE。两种情况下替换和 mirror 删除都无法完成        |
| 说明 / 主要证据                   | 补充限制，以及推断所依据的 OpenList 源码位置                                                                                                                    |
| 实测                              | 经本项目集成测试验证的操作；“—”表示未测试，不能由同一驱动其他操作的结果推定                                                                                     |

证据分三级，可信程度依次升高：

1. **源码推断**：Copy、Put、Remove 三列都来自阅读 OpenList v4.2.6 系列源码（上游 main 分支 2026-09 快照，提交 5447ecb0），没有运行过。驱动行为还可能随存储配置、云端服务变化或 OpenList 新版本改变。
2. **集成测试**：只有“实测”列。目前只有 Local 驱动：relay、Put、Remove 在 OpenList 4.2.7 和 4.2.5 上测过；server_copy 只测了 4.2.7 上 OpenList 回退为任务的路径，同步 reflink 未测。镜像版本和日期见[兼容版本记录](../reference/openlist-api.md#兼容版本)。
3. **人工验证**：你在自己的云盘上按下文步骤做的验证。它只对你的配置有效，单独记录，不会改变矩阵中的证据等级。

几类驱动需要特别注意：

- virtual、url_tree、strm、emby 等虚拟或索引驱动不是真正的文件内容存储，不能当作备份目标。virtual 的复制和删除是成功空实现，上传会丢弃数据：本服务会记成功，但数据并没有保存。
- 只读驱动（Put 列为“不可写”）只能作为源。
- “委托底层”的驱动（例如 openlist 驱动挂载另一个 OpenList）要连同远端实际使用的驱动一起考虑。

## 服务端复制在异步驱动上的风险

创建方式选“服务端复制”的 Target 按 OpenList 的复制结果判定：返回成功且没有任务即记为成功，有任务则跟踪任务终态。这对所有驱动一致，**包括只受理后台复制、不提供完成句柄的驱动**（例如矩阵中 Copy 列为“后台受理，不等待完成”的 onedrive、onedrive_app、189）。这是已接受的取舍，见 [ADR 0005](../adr/0005-openlist-success.md)，后果是：

- 后台复制失败在该 Run 内不可见，Run 照常显示成功；
- 替换时旧文件在复制前就已删除，mirror 模式的多余文件也可能已经删除，后台失败后目标上既没有旧文件也没有新文件；
- 运行历史和统计不会事后改写；
- 后续运行只有观察到缺失或大小不同才会重新规划，不保证自动修复（见下一节的 Temp 缓存）。

需要更可控的结果时，使用默认的“中转”（relay）：它以分片上传的 complete 结果为准。

## Temp 缓存“幽灵”与扫描刷新

OpenList 在 mkdir、复制、上传等操作成功后，如果驱动没有返回新对象，而目标目录已在缓存中，会按源对象或上传请求的名称和大小往该目录缓存里插入一个占位对象（Temp 标记）。在缓存过期或刷新之前，不带刷新的目录列表都会返回这个占位对象，即使云端实际还没有这个文件，或者后台复制已经失败。

本服务扫描目标时默认不刷新（Target 的“扫描目标时刷新”默认关闭，以减少云端 API 请求）。因此在异步驱动上，下一次运行可能把占位对象当成“同名同大小”，判为无变化，问题就一直不会被修复。缓解办法：

- 对使用异步驱动或需要验证结果的 Target 打开“扫描目标时刷新”（API 字段 `targets[].refresh=true`），代价是每次扫描都让 OpenList 重新向云端列目录，可能触发云端限流；
- 或者等 OpenList 存储设置中的目录缓存过期后再运行。

刷新要求账号对该路径有写权限，没有权限时 OpenList 返回 403，本服务把它当作读取失败，不会当作目录为空。删除前、删除确认和写操作出错后的观察，无论开关如何都会强制刷新。

## relay 中止后的迟到清理

relay 因源异常（大小不符、源已变化）或本地 spool 写入失败而主动 abort 上传时，该文件记为 failed。目标驱动可能稍后才清理被中止的写入，例如 Local 驱动在请求取消时删除已写入的部分文件；这次清理可能晚于同一 Run 内的重试，把重试写入的文件删掉。下一次运行会发现文件缺失并重新创建，源文件不受影响。这是已接受风险，见[需求中的已接受风险](../design/requirements.md#已接受风险)。

## 在自己的云盘上人工验证

在正式使用某个云盘驱动前，建议用一个专门的测试目录按下面步骤走一遍。全程只使用测试目录，不要指向已有数据。

### 准备

1. 在源存储上建一个测试源目录，放入：一个几 KB 的小文件；一个明显大于目标 OpenList 分片大小的大文件（OpenList 设置 `multipart_chunk_size`，默认 10 MiB；relay 操作详情中的“分片大小”显示实际值），用于覆盖多分片上传；一个 0 字节文件；一个子目录及其中的文件；一个名字含中文、空格和 `#` 的文件。
2. 在目标云盘上建一个空的测试目标目录。
3. 记下各文件大小，并在本地计算校验和（例如 `sha256sum`）。

### 步骤

| 步骤 | 操作                                                                                                       | 检查                                                                                                                                                           |
| ---- | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 在“实例”页对源和目标实例各做一次“测试连接”                                                                 | 状态为就绪；OpenList 版本不低于 4.2.5；用 relay 写入的目标实例分片上传已开启                                                                                   |
| 2    | 新建任务：源为测试源目录，一个 Target 指向测试目标目录，同步模式“增量”，创建方式“中转”；先做一次“预览运行” | 计划中每个文件都是新建，没有扫描问题                                                                                                                           |
| 3    | 真实运行                                                                                                   | Run 为成功；“操作”标签页中每个文件都是成功                                                                                                                     |
| 4    | 在 OpenList 网页中刷新目标目录                                                                             | 文件名、大小与源一致；下载回本地后校验和一致。只核对名称和大小不能证明内容正确                                                                                 |
| 5    | 不做任何修改，再真实运行一次                                                                               | 全部为无变化。如果反复出现替换，说明该驱动列出的大小不稳定                                                                                                     |
| 6    | 把源中一个文件改成不同大小，再运行                                                                         | 目标上旧文件被删除、新文件写入，大小与校验和正确                                                                                                               |
| 7    | 把 Target 改为“镜像”，在源中删除一个文件，先预览再真实运行                                                 | 预览中出现对应的删除；运行后目标上该文件被删除，其他文件不受影响                                                                                               |
| 8    | 仅当打算使用服务端复制，且源和目标是同一实例：把创建方式改为“服务端复制”，清空测试目标目录后重新运行       | 在操作详情中查看是否有“远端任务”。没有任务表示驱动同步返回或后台受理；等一段时间后在 OpenList 中刷新目标目录并核对大小和校验和，确认后台复制确实完成           |
| 9    | 可选：用一个大文件开始真实运行，上传中途取消                                                               | 该文件通常为 unknown；隔一段时间后在 OpenList 中刷新目标目录，观察是否残留部分文件或迟到清理。处理方法见[取消、重启和 unknown 处理](cancel-restart-unknown.md) |

### 记录

每次验证建议记录以下内容，便于之后对照：

- 日期、本服务版本（镜像标签或提交）、OpenList 版本（连接测试显示的版本字符串）；
- 驱动名称，以及影响行为的存储配置（不要记录任何凭据）；
- 拓扑：同实例同存储、同实例跨存储，或跨实例；
- 每个 Target 的同步模式、创建方式、是否开启“扫描目标时刷新”；
- 每个步骤的结果，以及异常 Operation 的错误码和信息；
- 校验和比对结果。

这份记录只证明你所测配置在当时的行为；OpenList 或驱动升级、存储配置变化后应重新验证。
