# ADR 0003：先删除再创建的替换

- 状态：accepted
- 日期：2026-10-19
- 决策者：项目维护者

## 背景

驱动 overwrite 行为包含报错、自动改名、重复和截断，不能作为统一的替换语义。

## 决策

changed 文件先用单名称 remove 删除旧文件，refresh 确认原名称消失，再以 overwrite=false 创建；无自动 rollback。relay 在删除前先打开源并写入首块，源不可用时不删除旧文件。

## 考虑的替代方案

- 原地 overwrite：各驱动语义不统一。
- 临时文件加原子 rename：不是跨驱动统一能力。
- 完整版本管理：延期。

## 后果

- 收益：所有驱动使用同一套可观察的替换步骤，不依赖各驱动的 overwrite 语义。
- 代价：替换需要额外的删除与确认刷新；替换和 extras 共同计入删除阈值。
- 已接受风险：目标有名称缺失窗口；create 失败时本服务没有保存旧版本，目标暂时缺少该文件，下一次 Run 按源重新创建。

## 落地规范

详见[删除保护](../design/deletion.md)与[同步引擎](../design/sync-engine.md#替换链)；默认值以[配置](../reference/configuration.md)为准。
