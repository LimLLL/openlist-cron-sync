# ADR 0004：未知结果的限时路径隔离

- 状态：accepted
- 日期：2026-10-19
- 决策者：项目维护者

## 背景

OpenList没有跨系统提交事务；本服务可在远端生效后丢响应，分片上传的init一执行就启动驱动写入，server_copy的任务也可能随重启消失。

## 决策

unknown只用于请求可能仍在执行或观察无法判定的情况，判定规则见[OpenList集成](../design/openlist-integration.md)。unknown保留历史；隔离相关目标路径及其祖先的删除，默认期限见配置，且不短于OpenList分片会话的闲置过期时间。到期或管理员提前释放后，写入前必须先refresh重新观察，再按观察重新规划；管理员abandon直接结束该记录。

## 考虑的替代方案

- 永久阻塞整个Job：影响无关路径，不采用。
- 按任务名字猜tid：不可靠，不采用。
- 路径隔离不自动到期（仅管理员release或后续观察解决）：迟到写入风险更低，但每个unknown都需人工介入，受影响路径可能无限期停止同步。维护者选择默认到期（期限见配置）并接受迟到写入风险。

## 后果

- 收益：无需人工即可恢复同步；只有受影响路径暂停，其他路径继续。
- 代价：隔离期间受影响路径不同步；到期后需要额外的refresh观察。
- 已接受风险：旧写入可能在隔离解除后到达，时间过去不证明远端已停止。OpenList报错后观察到原状态未变即按failed重试，同样接受迟到生效的小风险。
- 不提供的保证：分片上传的abort成功、session消失或过期都不证明驱动已停止写入。
